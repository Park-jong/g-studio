# game-concept

목표: **한 문장으로 설명되는 게임**과 **한 판의 흐름**을 정하고 문서로 남긴다. 세부 수치·유닛 목록은 4단계(`game-spec`)에서 정하므로 여기서 깊게 들어가지 않는다.

## 절차

1. **사용자가 이미 준 정보 정리** — 요청에 장르·참고 게임·테마가 있으면 그대로 쓴다. 없는 것만 묻는다.
2. **필요한 결정을 한 번에 묻는다** (AskUserQuestion, 최대 4문항). 이미 답이 있는 항목은 빼고:
   - 장르 (예: 플랫포머, 퍼즐, 슈팅, 디펜스, 덱빌딩, 로그라이크)
   - 플랫폼과 화면: PC만 / PC+모바일, 가로 / 세로
   - 한 판 길이: 1~3분 / 5~10분 / 30분 이상 런
   - 테마·분위기 (예: SF, 판타지, 현대 도시, 동화)
3. **콘셉트 후보 2~3개 제안** — 각 후보마다: 가제, 한 줄 소개, 핵심 재미 1개, 참고 게임과 다른 점 1개, 예상 개발 규모(작음/중간/큼). 추천 하나를 고르고 이유를 한 줄로 쓴다.
4. 사용자가 고르면(또는 섞자고 하면) **`docs/design.md`를 작성**한다. 파일이 이미 있으면 덮어쓰지 말고 해당 장만 채운다. 형식은 이 스킬 폴더의 `design-template.md`를 따른다 (1~2장만 채우고 3장 이후는 제목과 "(4단계에서 작성)"만 남긴다).
5. `TODO.md` 제목의 가제를 바꾸고, `## gamestudio 진행`의 1단계를 `[x]`로 바꾼다.
6. **보고** — 정해진 콘셉트를 3줄로 요약하고, 다음은 `/gamestudio:prototype`이라고 알린 뒤 멈춘다.

## 작성 원칙

- 장마다 상태를 붙인다: `(결정)` 사용자가 확정함, `(초안)` 제안만 함.
- **"넣지 않기로 한 것"** 을 반드시 쓴다. 범위를 줄이는 것이 이 단계의 가장 중요한 결과다.
- 핵심 루프는 "한 판의 흐름"(시작 → 반복 행동 → 끝나는 조건)과 "판 밖 흐름"(있다면 성장·해금)으로 나눠 쓴다.
- 문장은 한국어 평서문, 불릿 위주. 추측한 사용자 의도는 `(초안)`으로 둔다.
