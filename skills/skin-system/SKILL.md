# skin-system

스킨 = 한 캐릭터의 **외형 묶음**(이미지·동작 프레임·크기·기준점·방향). 전투 수치(체력, 공격력, 사거리, 충돌 반경 등)는 절대 바꾸지 않는다. 스캐폴드 템플릿의 `src/skins/`(SkinRegistry, SkinSelection, CharacterView)를 기반으로 확장한다.

시작할 때 사용자에게 어느 차수를 진행할지 확인한다 (기본: 아직 안 한 가장 낮은 차수). 각 차수는 `/gamestudio:dev-cycle`로 구현한다. 이 스킬은 **설계 문서·명세 작성과 dev-cycle 지시 내용 준비**를 맡는다.

## 0. 현재 코드 파악 (모든 차수 공통)

1. `src/skins/`가 있는지 확인한다. 없으면(템플릿 이전 프로젝트) `/gamestudio:scaffold`의 `template/src/skins/` 파일을 가져올지 묻는다.
2. 캐릭터 종류 정의(`src/data/*`의 id), 캐릭터를 그리는 곳(Graphics로 매 프레임 그리는지, 지속 객체인지), 바라보는 방향, 저장 코드(`session.ts`/`save.ts`)를 찾아 **연결 지점 표**를 만든다 (현재 파일 | 확인된 구조 | 연결할 내용).

## 1차: 이미지 없이 동작하는 구조

1. 이 스킬 폴더의 `skins-template.md`로 `docs/skins.md`를 작성한다 (연결 지점 표, 대상 키 목록, 화면, 저장 호환).
2. **대상 등록**: 모든 캐릭터 종류를 `분류:id` 대상 키로 `src/skins/skins.ts`에 `default` 스킨(현재 도형 색·크기를 `placeholder`로)과 함께 등록한다. 등록 누락을 막는 테스트를 넣는다 (데이터의 모든 id에 default 스킨이 있는지).
3. **표시 교체**: 캐릭터를 그리는 코드를 개체마다 `CharacterView`를 하나씩 갖는 구조로 바꾼다 (생성 시 만들고 제거 시 destroy). 전투 상태 → `play('walk'|'attack'|'hit'|'death')`, 방향 → `setFacing`, 피격 → `flashHit`.
4. **선택 화면**: 분류 탭 → 종류 목록 → 스킨 카드(이름, 미리보기, 적용 중 표시, 이미지 없으면 "이미지 준비 중"). 카드 선택은 미리보기만, `적용`을 누르면 저장. 미리보기에서 동작·좌우 전환 확인.
5. **저장**: `SaveData.skins`. 과거 저장에 없으면 기본값. 저장 버전을 올리지 않는다.
6. 완료 조건: 스킨을 데이터에만 추가해도 선택 화면에 나타남, `?skin=`으로 임시 적용, 저장·불러오기 테스트, 기존 테스트 전부 통과.

## 2차: 아트 명세와 대표 캐릭터 이미지

1. **아트 공통 규격** `docs/art/README.md` (`art-spec-template.md`의 공통 규격 부분):
   - 형식: PNG, 투명 배경, 한 동작 = 가로 스프라이트 시트 또는 프레임별 파일
   - 기준 크기: 캐릭터 프레임 정사각형(예: 128×128 또는 256×256), 발 위치 기준점 `origin {x:0.5, y:1}`, 원본은 **오른쪽을 바라봄**
   - 파일 위치: `public/assets/characters/<분류>/<id>/<skinId>/<동작>.png` (또는 `sheet.png`)
   - 색 규칙: design.md 8장의 태그 색을 따른다
2. **캐릭터별 명세** `docs/art/<분류>/<id>.md`: 외형 설명, 팔레트, 실루엣 특징, 동작별 필요한 프레임 수, 고유 효과, **이미지 생성 프롬프트**(공통 스타일 문구 + 캐릭터 문구, 동작별), 추가 스킨 콘셉트 2개.
3. **에셋 목록** `public/assets/characters/asset-manifest.json`: 파일별 `{ path, subjectKey, skinId, state, frameWidth, frameHeight, frames, status: "planned"|"ready" }`. 사용자가 이미지를 준비하면 status를 바꾼다.
4. 사용자에게 우선 만들 대표 캐릭터(주인공 + 아군 1 + 적 1 정도)를 고르게 하고, 이미지를 받으면 아래 **"이미지 적용"** 절차로 등록한다.

## 3차: 전체 확장

- 나머지 캐릭터의 공격·소환·퇴장 프레임, 보스 고유 동작, 추가 스킨. 배경·투사체·UI 스킨은 필요할 때 같은 등록 구조로 분류를 추가한다 (예: `bg:stage1`).

## 이미지 적용 절차 (사용자가 이미지를 줄 때마다)

1. 받은 파일을 규격 위치로 옮기고(이름 규칙에 맞게), 이미지 크기를 읽어 프레임 크기·개수를 확인한다. 규격과 다르면(투명 배경 아님, 크기 불일치, 방향 반대) 그대로 쓸지, `facing: 'left'`·`displayHeight`로 맞출지 보고한다.
2. `src/skins/skins.ts`에 `ASSETS` 항목(url은 `assets/...` 상대 경로)과 스킨의 `assetKey`·`clips`·`origin`·`displayHeight`를 추가한다. 새 스킨이면 새 `skinId`로 추가한다.
3. `asset-manifest.json`의 status를 `ready`로 바꾼다.
4. `npm test`, `npm run build` 후 개발 서버에서 `?skin=<대상키>:<skinId>`(필요하면 `?stage=N`과 함께)로 열어 표시·애니메이션·좌우 반전·크기를 확인한다. 가능하면 스크린샷으로 보고한다.

## 규칙

- 스킨이 바뀌어도 판정(충돌 반경·사거리)은 그대로다. 이미지가 커 보여도 판정 크기를 바꾸지 않는다.
- 이미지가 없거나 로딩에 실패해도 도형으로 표시되어야 한다 (빈 캐릭터 금지).
- 1차 범위에 구매·해금·희귀도는 넣지 않는다. 필요하면 별도 단계로 계획한다.
- 끝나면 `TODO.md`의 해당 단계와 `## gamestudio 진행` 8단계(3차까지 끝났을 때)를 갱신한다.
