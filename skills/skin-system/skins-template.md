# 스킨 등록·선택 및 캐릭터 애니메이션 설계

작성일: YYYY-MM-DD · 상태: 구현 전 설계 · 이미지 제작 규격은 [아트 가이드](art/README.md)

## 1. 목표와 우선순위

스킨은 한 캐릭터의 외형 묶음이다 (동작별 이미지, 표시 크기, 기준점, 기본 방향). 전투 수치는 바꾸지 않는다.

1. **1차**: 이미지 없이도 동작하는 스킨 등록·선택·저장·대체 표시 구조
2. **2차**: 대표 캐릭터의 이미지 표시, 좌우 반전, 걷기, 피격 표현
3. **3차**: 전체 캐릭터의 공격·소환·퇴장 프레임, 보스 고유 동작, 추가 스킨

## 2. 현재 코드와 연결 지점

| 현재 파일 | 확인된 구조 | 연결할 내용 |
| --- | --- | --- |
| `src/data/...` | 종류별 `id`와 수치 | 기존 ID를 대상 키에 사용 |
| (캐릭터를 그리는 씬) | | 개체마다 `CharacterView` 유지 |
| (방향을 가진 엔티티) | | `setFacing` 기준 |
| (저장) | | `SaveData.skins` 추가, 버전 유지 |

## 3. 대상 키 목록

| 분류 | 대상 키 | 이름 | default 도형 |
| --- | --- | --- | --- |
| hero | `hero:<id>` | | rect, 색 |

- 대상 키 = `분류:종류ID`, 스킨 ID = `default` / `<콘셉트>`. 표시 이름·파일 경로는 식별자로 쓰지 않는다.
- 강화·변신·보스 패턴 같은 **전투 상태는 스킨이 아니다** (크기 배율·효과로 표현).

## 4. 데이터 구조

`src/skins/skinTypes.ts`의 `SkinDef`, `AssetDef`를 쓴다. 새 스킨 추가 = `src/skins/skins.ts`에 데이터 추가 + 이미지 파일. 전투 로직·선택 화면의 조건문은 수정하지 않는다.

## 5. 선택 화면과 저장

- 진입: 타이틀 또는 지도에서 `외형` 버튼
- 분류 탭 → 종류 → 스킨 카드 (미리보기, 적용 중 표시, "이미지 준비 중")
- 카드 선택 = 미리보기, `적용` = 저장, 뒤로 = 미적용 선택 버림
- 전투 시작 때 선택을 복사해 그 판 전체에 적용 (전투 중 변경은 후순위)
- 저장 호환: `skins` 필드가 없거나 잘못된 선택은 기본값. 저장 버전을 올리지 않는다.

## 6. 동작 상태

| 상태 | 언제 | 없을 때 |
| --- | --- | --- |
| idle | 정지 | 정지 프레임 |
| walk | 이동 중 | idle |
| attack | 공격 시작 ~ 타격 | idle |
| hit | 직접 타격 (지속 피해는 제외) | 깜박임만 |
| spawn / death | 등장 / 퇴장 | 페이드 |

## 7. 완료 조건 (차수별)

- 1차: 데이터 추가만으로 목록에 나타남, `?skin=` 임시 적용, 저장 테스트, 기존 테스트 통과
- 2차: 대표 캐릭터 이미지 표시·반전·걷기·피격, 로딩 실패 시 도형
- 3차: 전체 동작, 추가 스킨
