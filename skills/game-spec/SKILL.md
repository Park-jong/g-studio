# game-spec

목표: 개발 에이전트가 **추측 없이 구현할 수 있을 만큼** 규칙과 수치를 문서로 정한다. 문서에 없는 값은 6단계에서 매번 질문거리가 되므로, 여기서 최대한 정해 둔다.

## 절차

1. `docs/design.md`(1~2장, 9장 프로토타입 교훈)와 `prototype/index.html`의 `CONFIG`를 읽는다.
2. **장 단위로 진행**한다. 한 장마다:
   1. 결정이 필요한 항목을 2~4개로 묶어 묻는다 (AskUserQuestion). 질문마다 추천안을 첫 선택지로 둔다.
   2. 답을 받으면 해당 장을 작성하고 `(결정)`을 붙인다. 사용자가 "알아서 해줘"라고 하면 추천안으로 쓰고 `(초안)`으로 둔다.
   3. 한 장이 끝나면 한 줄로 알리고 다음 장으로 간다.
   - 순서: 3. 주인공·조작 → 4. 등장 요소 → 5. 자원·경제 → 6. 판 밖 성장 → 7. 화면·조작 → 8. 아트·사운드
   - 게임에 없는 장(예: 판 밖 성장이 없는 게임)은 "없음(넣지 않기로 함)"으로 남긴다.
3. **`docs/numbers.md` 작성** — design.md에서 정한 모든 수치를 표로 모은다 (아래 형식).
4. **검토** — 두 문서를 다시 읽고 아래를 확인해 사용자에게 보고한다.
   - design.md와 numbers.md의 수치가 서로 맞는지
   - 정해지지 않은 값 목록 → `TODO.md`의 `## 결정 대기`에 추가 (섹션이 없으면 만든다)
   - 한 판 길이 목표와 수치가 대략 맞는지 (예: 적 체력 × 수 ÷ 아군 DPS)
5. `TODO.md`의 `## gamemanager 진행` 4단계를 `[x]`로 바꾸고, 다음은 `/gamemanager:roadmap`이라고 알린 뒤 멈춘다.

## design.md 작성 기준

- **등장 요소**: 종류마다 `id`(영문 camelCase, 코드·스킨 대상 키에 그대로 쓰임), 이름, 역할, 특징 한 줄. 상성·태그 체계가 있으면 표로 먼저 정의한다.
- **화면·조작**: 화면 흐름(Boot → Title → ... ), 주요 화면의 배치(기준 해상도 좌표 또는 영역), PC 조작, 모바일 조작(버튼 최소 크기 66px), 피드백 표시(데미지 숫자, 색 규칙).
- **아트·사운드**: 처음에는 도형 그래픽으로 개발하고 8단계에서 이미지 스킨으로 바꾼다는 전제를 적는다. 색 규칙(태그별 색), 캐릭터 크기 기준, 배경 방향, 사운드 목록을 정한다. 이 장이 8단계 아트 명세의 바탕이 된다.
- 장마다 `### 넣지 않기로 한 것`을 둔다.

## numbers.md 형식

```markdown
# 세부 수치 (초안 v1)

플레이 테스트로 조정한다. 코드의 `src/data/`가 이 문서와 일치해야 하며, 수치를 바꾸면 둘 다 바꾼다.

## 1. <분류> (예: 아군 유닛)
| id | 이름 | 체력 | 공격력 | 공격 간격(초) | 사거리 | 이동 속도 | 비용 | 비고 |
|---|---|---|---|---|---|---|---|---|

## N. 공식
- 피해 = ... (최소 1, 감소 상한 70% 등 경계 규칙 포함)
```

- 단위(초, px, px/초, %)를 열 이름에 적는다.
- 공식은 경계 규칙(최소값, 상한, 반올림 방식)까지 쓴다.
