# roadmap

목표: 6단계 개발에서 **"N단계 시작해"라고만 말하면 되는** 작업 목록. 각 단계는 dev-cycle 한 번(또는 A/B/C로 나눈 몇 번)으로 끝나는 크기이고, 끝나면 플레이 가능한 상태로 배포된다.

## 절차

1. `docs/design.md`, `docs/numbers.md`, 기존 `TODO.md`를 읽는다.
2. **단계 나누기** — 아래 기본 골격에서 시작해 게임에 맞게 조정한다.

| 단계 | 내용 | 버전 |
|---|---|---|
| 0 | 설계(완료) | – |
| 1 | 뼈대 정리 + 데이터 분리(`src/data`) + 핵심 루프 최소 구현 (데모 화면 교체) | 0.1.0 |
| 2 ~ k | 핵심 시스템을 하나씩 (예: 적 종류 → 특수 능력 → 스테이지 구성 → 보스) | 단계마다 MINOR |
| k+1 | 화면 흐름 (타이틀·지도·설정·결과), HUD 정식 배치, PC·모바일 조작 | MINOR |
| k+2 | 판 밖 성장·저장 (있다면) | MINOR |
| k+3 | 스킨 구조 (`/gamestudio:skin-system` 1차: 이미지 없이 등록·선택·저장) | MINOR |
| k+4 | 아트·사운드 적용 (스킨 2~3차: 이미지·애니메이션, 사운드) | MINOR |
| k+5 | 밸런스·플레이 테스트 → 1.0.0 후보 | – |

   - 한 단계가 dev-cycle 한 번에 안 끝날 것 같으면 `A/B/C`로 나눈다 (예: 3-A 코어 로직 / 3-B 화면 연결). 기준: 바뀌는 파일 10개 이하, 완료 조건 5개 이하.
   - **로직(Phaser 비의존, 테스트 가능)과 화면 연결을 나누는 것**을 기본으로 한다.
3. **계획 사전 검토** — 단계 구성이 정해지면, 이 순서대로 개발하면 생길 문제를 한 번 따져 보고 대안을 찾는다. 예: 뒤 단계에서 앞 단계 구조를 뜯어고쳐야 함(저장 형식·데이터 구조를 늦게 정함), 한 단계가 너무 커서 dev-cycle 한 번에 안 끝남, 플레이 가능한 상태가 너무 늦게 나옴, 스킨 구조 전에 캐릭터 표시 코드가 굳어짐. 근거 있는 문제만 많아야 5개, 문제마다 대안(순서 바꾸기·단계 나누기·먼저 정할 것)과 추천을 적는다. 대안을 반영해 단계를 고치고, 단계 수나 범위가 크게 바뀌면 사용자에게 확인한다. 각 단계에 남는 위험은 `위험:` 줄로 남긴다.
4. 이 스킬 폴더의 `todo-template.md` 형식으로 `TODO.md`를 작성한다. `TODO.md`는 dev-team 조직의 전체 로드맵이기도 하다 (단계 = 마일스톤, 타 팀 요청 우선순위의 기준). 기존 `## gamestudio 진행` 섹션은 그대로 유지하고 5단계를 `[x]`로 바꾼다.
5. **보고** — 단계 목록과 계획 사전 검토 결과를 표로 보여주고, 다음은 `/gamestudio:dev-cycle`로 1단계를 시작하면 된다고 알린 뒤 멈춘다. 배포 설정(`/gamestudio:deploy-setup`)이 아직이면 먼저 하자고 권한다.

## 항목 작성 기준

- 항목 하나 = 검증 가능한 결과 하나. "전투 구현"이 아니라 "플레이어가 방향키로 이동하고 점프한다 (numbers.md 2장 수치)".
- 각 단계에 **목적(왜)**(이 단계가 끝나면 무엇이 가능해지는지, design.md 근거), **완료 조건(무엇)**(테스트·빌드 통과, 확인용 URL로 무엇을 볼 수 있는지), **범위 밖**을 적는다. 항목마다 "— 왜:"를 한 줄 붙인다. 목적을 design.md에서 찾을 수 없는 단계·항목은 넣기 전에 사용자에게 묻는다.
- 수치는 numbers.md의 장 번호로 참조하고 숫자를 복사하지 않는다 (두 곳에서 어긋나는 것 방지).

## 개발 중 갱신 규칙 (dev-cycle과 커밋에서 따른다)

- 단계 완료 시: 항목 `[x]`, 완료 표에 버전·커밋 해시 추가, `## 현재 상태` 갱신 (버전, 테스트 개수, 배포 주소).
- 검증에서 나온 **낮음 문제**와 다른 팀에 넘길 일은 타 팀 요청(`mcp__gamestudio__route_request`, 보통 P2~P3)으로 기록한다.
- 중요한 결정은 `## 결정 기록`에 날짜와 이유를 남긴다.
- 문서에 없어서 코드가 정한 값은 `## 코드가 정한 해석`에 남긴다.
- 사용자가 결정해야 하는 것은 `## 결정 대기`에 넣는다.
