## 진행 원칙
- 사용자가 시작하라고 한 항목만 진행하고, 끝나면 멈추고 보고한다.
- 코드 작업은 dev-cycle(개발 팀 구현 → QA 팀 검증·피드백, 최대 3사이클)로 진행한다. 사용자가 "개발만" 하라고 하면 QA를 건너뛰고 그 사실을 보고한다.
- 단계 안에서 다른 팀에 넘길 일과 남은 낮음 문제는 타 팀 요청(`.dev-team/requests.md`, P0~P3)으로 기록한다.
- 문서에 없는 값은 구현 전에 정해서 지시하고, 정한 내용은 아래 "코드가 정한 해석"에 남긴다.
- 커밋은 요청이 있을 때 commit-release 규칙(버전·CHANGELOG 확인 후 커밋)으로 한다. push(=배포)는 commit-release 확인 화면에서 `커밋 후 push`를 골랐을 때만 한다.
